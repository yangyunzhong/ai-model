# 组件文档生成

为 `@st/platform-ui` 中的组件生成结构化的 Markdown 说明文档，存放于 `apps/demokit/src/docs/components/` 目录下，文件名与组件 id 一致。

## 输出路径

```
ruoyi-plus-vben5/apps/demokit/src/docs/components/{component-id}.md
```

其中 `{component-id}` 与 `apps/demokit/src/registry.ts` 中 `componentRegistry` 的 `id` 字段一致（如 `platform-button`、`platform-table`）。

## 文档模板

## 章节填写规则

### 1. 组件概述（## {ComponentName}）

- 用一段话说明组件的功能定位、底层依赖和封装方式
- 必须提到基于哪个底层库的哪些组件封装
- 必须说明"页面层优先使用它承接"什么场景
- 参照示例：`PlatformButton 是平台按钮的统一入口，基于 antdv-next 的 Button、Dropdown、Popover 和 SpaceCompact 组合封装。页面层优先使用它承接普通按钮、工具栏按钮、行操作按钮、收起按钮、二次确认和菜单组合按钮。`

### 2. 组件来源（### 组件来源）

- 列出主要底层组件的库名和组件名
- 提供底层组件的官方文档链接
- 如果组件没有直接对应的底层组件（纯自建），写"平台自建组件"并说明设计参考

### 3. 什么时候使用（### 什么时候使用）

- 用 bullet list 列出 3-6 个典型使用场景
- 每条格式：`{场景概括}：{具体操作举例}`
- 场景顺序按使用频率从高到低排列
- 必须覆盖组件所有主要使用场景

### 4. 基础用法（### 基础用法）

- 一段简短说明（1-2 句）
- 紧跟最简代码示例，展示最常用的 2-5 种基本形态
- 代码必须是可运行的 Vue SFC 片段
- 不需要 `<script setup>` 除非示例需要引入额外依赖

### 5. 特性/场景章节（### {特性名称}）

- 每个组件的重要特性或使用场景独立一节
- 章节标题用特性名称，不用"高级用法"等泛化标题
- 每节结构：说明文字 → 代码示例
- 说明文字必须包含：此特性的作用、行为细节、注意事项
- 代码示例必须完整可运行，需要 `<script setup>` 时必须包含
- 特性章节数量根据组件实际能力决定，通常 2-6 个

### 6. Props（### Props）

- 列出组件自身定义的所有 props（非透传）
- 格式：`- {propName}?: {TypeScript 类型}：{中文说明}，默认 {默认值}。`
- 可选属性用 `?` 标记
- 如果组件通过 `v-bind="$attrs"` 透传底层组件属性，在末尾补充透传说明
- 透传说明格式：`组件会继续透传 {列举常用透传属性} 等 {底层库名} {底层组件名} 属性。`

### 7. Emits（### Emits）

- 列出组件定义的所有 emits
- 格式：`- {emitName}({参数类型})：{中文说明}。`
- 如果组件没有自定义 emits，写"无自定义事件，点击行为通过透传的 `onClick` 处理。"

### 8. 设计约束（### 设计约束）

- 列出使用此组件时必须遵守的规则
- 通常 3-5 条
- 最后一条固定格式：`{ComponentName} 是平台能力入口，页面里不要重复手写一套{被替代的原生结构}。`
- 约束内容来源：组件封装的设计意图、避免重复造轮子、视觉一致性要求

## 代码示例规范

1. 所有 Vue 代码使用 `<script setup lang="ts">` + `<template>` 结构
2. import 路径使用 `@st/platform-ui` 而非相对路径
3. 类型 import 使用 `import type` 语法
4. 示例代码必须可直接复制到业务页面运行
5. 事件处理函数命名使用 `handle{Action}` 格式
6. 不使用 `any` 类型，给出具体类型

## 信息来源

生成文档前，必须阅读以下文件获取准确信息：

1. **组件源码**：`packages/platform-ui/src/{component-dir}/` 目录下所有 `.vue` 和 `.ts` 文件
2. **组件导出**：`packages/platform-ui/src/{component-dir}/index.ts`
3. **类型定义**：组件目录下的 `types.ts`（如有）
4. **Demo 示例**：`apps/demokit/src/demos/{component-demo}.vue`
5. **Registry 注册**：`apps/demokit/src/registry.ts` 中对应组件的 `api`、`scenarios`、`description` 字段
6. **底层组件文档**：antdv-next 官方文档中对应组件的 API 页面

## 质量检查

文档生成后，逐项确认：

- [ ] 组件概述是否提到了底层依赖和封装方式
- [ ] 组件来源是否提供了官方文档链接
- [ ] "什么时候使用"是否覆盖了所有主要场景
- [ ] 基础用法代码是否可运行
- [ ] 每个特性章节是否有说明 + 可运行代码
- [ ] Props 是否列出了所有自定义 prop（含类型和默认值）
- [ ] Emits 是否列出了所有自定义事件
- [ ] 设计约束是否包含"不要重复手写"条目
- [ ] 代码示例是否使用 `<script setup lang="ts">`
- [ ] 代码示例是否使用 `@st/platform-ui` 导入路径
