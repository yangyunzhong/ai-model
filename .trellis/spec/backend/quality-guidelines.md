# 后端质量规范

## 必须遵守

- 先复用 RuoYi-Vue-Plus 现有通用能力：`ruoyi-common-*`、工具类、注解、分页、权限、Excel、日志。
- Controller 保持薄层，业务规则进入 Service。
- Mapper 只处理数据访问，不承载业务判断。
- 新增接口必须同步考虑权限码、操作日志、参数校验、租户/数据权限、导入导出和前端调用方式。
- 增删改接口必须确认是否需要 `@Log` 和 `@RepeatSubmit`。
- 数据查询必须确认是否涉及数据权限或租户隔离。

## 禁止模式

- 禁止在业务模块中复制一份已有 common 工具。
- 禁止为了单个需求修改框架公共能力而不评估影响范围。
- 禁止 Controller 直接查 Mapper。
- 禁止随意新增全局配置、拦截器、过滤器。
- 禁止把 Entity 直接暴露为前端响应对象。
- 禁止绕过 Sa-Token 权限注解，让前端按钮权限成为唯一防线。

## 代码生成后的整理

生成器适合起步，不代表最终实现。生成后至少检查：

1. 权限码是否符合菜单和按钮设计。
2. BO/VO 字段是否贴合业务，不把数据库字段无脑暴露给前端。
3. 查询条件是否需要数据权限、租户和默认排序。
4. 删除前是否需要引用校验。
5. 导入导出字段、字典翻译、脱敏是否正确。

## 验证要求

- 文档/规范改动：至少运行 `git diff --check`。
- 后端代码改动：优先运行目标模块 Maven 编译或测试；无法完整编译时说明阻断原因。
- 涉及 SQL/Mapper：至少检查 XML、Mapper 方法、Service 调用三者签名一致。
- 涉及权限：核对权限码与前端 `v-access:code` 或菜单按钮配置一致。

## 评审清单

- 返回结构是否使用 `R` / `TableDataInfo`。
- 是否保留多租户和数据权限。
- 是否有必要的参数校验。
- 写操作是否有日志和防重复提交。
- 是否复用框架工具而不是自造基础设施。
