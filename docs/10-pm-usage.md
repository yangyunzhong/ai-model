# PM 使用说明

## PM 只需要做什么

PM 只需要说明业务，不需要说明技术。

AI 助手会在后台把原型工作纳入 Trellis 原型任务，记录需求、设计方案、产物位置、预览验证和待确认问题；PM 不需要知道或操作 Trellis。

可以提供：

- 业务背景
- 用户角色
- 页面清单
- 字段名称和含义
- 操作流程
- 状态流转
- 客户演示重点
- 截图、草图、旧系统页面或参考链接

## 推荐说法

```text
帮我生成一个能给客户看的产品原型。

业务目标：
用户角色：
需要的页面：
核心字段：
主要流程：
客户最关心：
```

## PM 不需要说什么

- 用什么框架
- 怎么装依赖
- 怎么跑项目
- 接口怎么设计
- 数据库怎么建
- 代码放哪里

## PM 会拿到什么

- 可运行的前端 mock 原型
- 预览地址
- 模拟数据
- 页面说明
- 字段说明
- draft API 协议设计
- draft 数据库/数据模型设计
- 待确认问题
- 原型确认后的开发交接包
- 后台保存的 Trellis 原型任务记录

其中 draft API 协议和 draft 数据库/数据模型是给开发看的技术草案。PM 不需要判断这些协议、字段类型、索引或表关系是否合理。

## 确认标准

PM 只确认：

- 页面是否表达了真实业务
- 字段是否正确
- 流程是否正确
- 状态是否合理
- 客户是否能看懂
- 前端 mock 原型是否能运行、预览和演示

技术正确性由后续开发阶段处理。

## 自动化验证

PM 原型阶段默认只给预览地址和手动检查路径，不自动跑 Playwright、批量截图或视频录制。

如果需要更严格的浏览器自动化验证，可以明确说：

```text
需要自动化浏览器验证，并保存关键页面截图。
```

AI 助手也可以在发现明显页面空白、布局错位或关键流程风险时先询问是否执行自动化验证。
