# UI 使用说明

## UI 负责什么

UI 负责让原型更接近可用产品，而不是负责最终工程实现。

UI 对原型的调整也属于 Trellis 原型任务的一部分。AI 助手负责把布局、状态、交互和待确认问题更新到当前原型 task；UI 不需要直接操作 Trellis。

UI 可以补充：

- 页面布局
- 信息层级
- 组件状态
- 空状态、加载态、错误态
- 表单交互
- 列表展示优先级
- 视觉风格建议
- 响应式要求

## 使用方式

推荐说法：

```text
根据下面的 UI 调整要求更新当前原型。
重点调整页面布局、组件状态、空状态和错误态。
```

## UI 不需要决定什么

- 最终后端接口
- 最终数据库字段
- Controller/Service/Mapper
- 最终代码结构

## 输出

- 更新后的前端 mock 原型
- 当前 Trellis 原型 task 中的变更记录
- 页面状态说明
- 视觉和交互说明
- 对 draft API 协议和 draft 数据模型的字段、状态、流程疑问
- 需要 PM 再确认的问题
